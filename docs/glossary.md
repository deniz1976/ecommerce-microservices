# Glossary

This document explains project terms in simple language.

## Microservice

A small application responsible for one business capability.

Example:

```text
Basket Service handles basket logic.
Inventory Service handles stock logic.
Payment Service handles payment logic.
```

Instead of one huge application, we split the system into smaller services.

## Service Boundary

The ownership line of a service.

Example:

```text
Inventory owns inventory_items.
Ordering should not directly update inventory_items.
```

Services communicate through APIs or messages, not by directly changing each other's tables.

## Database Per Service

Each service has its own database.

Example:

```text
ordering_db belongs to Ordering.
inventory_db belongs to Inventory.
payment_db belongs to Payment.
```

Why:

- Clear ownership.
- Less coupling.
- Independent migrations.

## API

API means a service endpoint that another client or service can call.

Example:

```text
POST /api/v1/orders
```

This creates an order.

## API Gateway

A single entry point in front of backend services.

In this project:

```text
Ocelot API Gateway
```

Example:

```text
Client calls /gateway/orders.
Gateway forwards to Ordering API.
```

## Ocelot

A .NET API Gateway library.

It routes external URLs to internal services.

In our project:

```text
/gateway/catalog/products -> Catalog API
/gateway/orders -> Ordering API
/gateway/users -> Identity API
```

## DTO

Data Transfer Object.

A simple object used to carry data between layers or over the network.

Example:

```text
CreateOrderRequest
OrderResponse
ProductResponse
```

DTOs are not business entities. They are request/response shapes.

## Domain Entity

A business object with rules.

Example:

```text
Order
InventoryItem
Payment
Shipment
Basket
```

These objects contain behavior such as reserving stock or calculating totals.

## Aggregate

A domain object that owns related child objects and protects business consistency.

Example:

```text
Order aggregate owns OrderItems.
Basket aggregate owns BasketItems.
```

Code should change the aggregate through its own methods instead of randomly changing child data.

## Repository

A class that hides database access behind an interface.

Example:

```text
IOrderRepository
OrderRepository
```

Application code calls repository methods. Infrastructure code decides how EF Core reads/writes the database.

## EF Core

Entity Framework Core.

It is the .NET ORM used to map C# classes to database tables.

Example:

```text
Order -> orders table
OrderItem -> order_items table
```

## DbContext

EF Core class that represents a database session.

Example:

```text
OrderingDbContext
InventoryDbContext
CatalogDbContext
```

It knows which tables exist and how entities map to them.

## Migration

A database schema change generated by EF Core.

Example:

```text
Create orders table.
Add postal_code column.
Create inventory_items table.
```

Running migrations updates the real database schema.

## PostgreSQL

Relational database system used for durable business data.

In this project PostgreSQL is hosted on Neon.

## Neon

Managed PostgreSQL provider.

It hosts our service databases:

```text
catalog_db
ordering_db
inventory_db
...
```

## Redis

Fast in-memory key/value store.

In this project Redis stores active basket state.

Why:

- Basket changes often.
- Basket is temporary.
- Redis is faster and lighter than writing every basket change to PostgreSQL.

## RabbitMQ

Message broker.

Services put messages into RabbitMQ and other services receive them.

Example:

```text
Ordering publishes OrderSubmitted.
Saga receives OrderSubmitted.
```

## CloudAMQP

Managed RabbitMQ provider.

It hosts RabbitMQ for us instead of running RabbitMQ locally in production.

## Message

A piece of data sent through RabbitMQ.

Example:

```text
OrderSubmitted
ReserveInventory
PaymentAuthorized
```

## Event

A message that says something already happened.

Example:

```text
OrderSubmitted means an order was submitted.
PaymentAuthorized means payment was authorized.
ShipmentCreated means shipment was created.
```

## Command

A message that asks another service to do something.

Example:

```text
ReserveInventory means please reserve stock.
AuthorizePayment means please authorize payment.
CreateShipment means please create shipment.
```

## Consumer

Code that receives and handles a message.

Example:

```text
ReserveInventoryConsumer handles ReserveInventory.
AuthorizePaymentConsumer handles AuthorizePayment.
```

## Publisher

Code that publishes a message.

Example:

```text
Ordering publishes OrderSubmitted.
Inventory publishes InventoryReserved.
```

## Exchange

RabbitMQ routing point.

Simple explanation:

```text
Messages are published to exchanges.
Exchanges route messages to queues.
```

MassTransit creates exchanges for message types.

## Queue

RabbitMQ storage area for messages waiting to be processed.

Simple explanation:

```text
A queue holds messages until a consumer receives them.
```

Example:

```text
Inventory has a queue for ReserveInventory messages.
```

## Binding

RabbitMQ connection between an exchange and a queue.

Simple explanation:

```text
Binding tells RabbitMQ which queue should receive messages from which exchange.
```

## MassTransit

.NET messaging library used on top of RabbitMQ.

It handles:

- consumers
- publishers
- RabbitMQ topology
- inbox/outbox tables
- message delivery plumbing

## Outbox Pattern

Pattern that prevents losing outgoing messages.

Problem:

```text
Service saves data to DB but crashes before publishing message.
```

Solution:

```text
Save outgoing message into the same service DB first.
MassTransit publishes it later.
```

In our project:

```text
OutboxMessage
OutboxState
```

## Inbox Pattern

Pattern that prevents processing the same incoming message twice.

Problem:

```text
RabbitMQ can deliver the same message again.
```

Solution:

```text
Track received messages and make processing idempotent.
```

In our project:

```text
InboxState
stock_reservations
```

## Idempotency

Doing the same operation twice has the same final result as doing it once.

Example:

```text
Reserve inventory for Order 123.
If the same command arrives again, do not reserve stock again.
```

## Saga

A pattern for coordinating a long-running business workflow across multiple services.

Example:

```text
Order workflow:
reserve inventory -> authorize payment -> create shipment
```

There is no single database transaction across all services, so saga tracks progress and compensation.

## Compensation

Undo or repair action when a later workflow step fails.

Example:

```text
Payment succeeded but shipment failed.
Then refund payment and release inventory.
```

## Eventual Consistency

The system becomes consistent after messages are processed.

Example:

```text
Order is submitted now.
Inventory/payment/shipping finish shortly after.
```

It is different from one immediate database transaction.

## SignalR

.NET realtime communication library.

In this project Notification service uses SignalR to push live notifications to connected clients.

## Hub

SignalR endpoint clients connect to.

In this project:

```text
/hubs/notifications
```

## Health Check

Endpoint used to check whether a service is alive or ready.

Examples:

```text
/health/live
/health/ready
```

## Smoke Test

A quick runtime check that verifies the system basically works.

It is not a full test suite.

In this project smoke test checks:

```text
gateway health
service health
user registration
inventory stock setup
order creation
```

## Integration Test

A test that checks multiple components together.

Example:

```text
API + PostgreSQL + RabbitMQ
```

## Unit Test

A small test for one class or behavior.

Example:

```text
InventoryItem reserve/release behavior.
OrderService validation behavior.
```

## Contract Test

A test that protects shared contracts.

Example:

```text
OrderSubmitted must contain shipping address fields.
RabbitMqOptions must parse amqps URI.
```

## Docker

Tool to run applications in containers.

Each API can run as a container.

## Docker Compose

Tool to run multiple containers together.

In this project it starts:

- APIs
- gateway
- saga worker
- Redis

## Container

Packaged runtime process.

Example:

```text
catalog-api container
basket-api container
redis container
```

## Environment Variable

Configuration value passed to the process.

Example:

```text
ConnectionStrings__OrderingDb
RabbitMq__ConnectionString
Redis__ConnectionString
```

## Secret

Sensitive value.

Examples:

- database password
- RabbitMQ password
- API key

Secrets should not be committed to git.

## OIDC

OpenID Connect.

Authentication standard used for login and identity providers.

The project is OIDC-ready, but token issuing is not implemented yet.

## JWT

JSON Web Token.

A signed token sent by clients to prove identity.

The project can validate JWT when auth config is provided.

## OpenTelemetry

Observability standard for traces and metrics.

The project has OpenTelemetry setup helpers, but dashboards/exporters are not finalized.

## OTLP

OpenTelemetry Protocol.

Used to send telemetry data to observability backends.
